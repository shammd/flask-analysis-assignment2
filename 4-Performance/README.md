# Flask performance analysis (Section 4 of the report)

Scripts, configuration and raw data for the performance metrics in Section 4.
Analyzed system: Flask 3.1.3, commit `22d924701a6ae2e4cd01e9a15bbaf3946094af65`.

## Which report files belong to

| Report                                    | Script                | Configuration                 | Results                       |
| ----------------------------------------- | --------------------- | ----------------------------- | ----------------------------- |
| 4.2, Metric 1: per-request overhead       | `measure_overhead.py` | `apps.py`, `requirements.txt` | `results/overhead/`           |
| 4.2, Metric 2: calls and time per request | `profile_calls.py`    | `apps.py`                     | `results/profile/<session>/`  |
| 4.2, Metric 3: overhead across versions   | `compare_versions.py` | `apps.py`, `versions/*.txt`   | `results/versions/<session>/` |

The result folders contain only the measurement sessions reported in the report.

## Setup for Reproducibility

Requirements: Python 3.13 (all results were produced with 3.13) and Git.
Commands below are for Windows PowerShell; on macOS/Linux use `source venv/bin/activate`.

```
git clone https://github.com/pallets/flask.git flask-src
git -C flask-src checkout 22d924701a6ae2e4cd01e9a15bbaf3946094af65

python -m venv venv (creates a venv folder)
venv\Scripts\Activate.ps1
pip install -r requirements.txt
pip install -e flask-src
```

`pip install -e flask-src` installs Flask from the clone, so Metric 1 measures exactly the analyzed commit.
The output file `overhead_env_*.json` records the commit, so this can be verified afterwards.

## Running the measurements

**Metric 1:** per-request overhead of Flask 3.1.3:

```
python measure_overhead.py
```

**Metric 2:** function calls and time distribution per request (under a minute):

```
python profile_calls.py
```

Output per session folder: `groups.csv` (calls and time per group: Flask, Werkzeug, stdlib, ...),
`lifecycle_flask.csv` (time per step of Flask's request lifecycle), `functions_<app>.csv` (every function),
`<app>.prof` (raw cProfile data, viewable with e.g. `snakeviz`) and `profile_env.json`
(including the measured profiler slowdown). Call counts are exact; times under the profiler are inflated,
so the time *shares* are the meaningful result.

**Metric 3:** the same measurement as Metric 1 for every configuration in `versions/` (a few minutes):

```
python compare_versions.py
```

The first time, this creates one virtual environment per configuration in `venvs/` and installs the exact
packages from `versions/<name>.txt`. It checks the installed Flask and Werkzeug versions before measuring.
All environments use the Python that runs the script, so every configuration is measured with the same Python.

The list of configurations is measured several times (`--rounds`, default 3), reversing the order every other
round so that drift during a session does not systematically favour some versions.
